# BetterPortal 11.0.0

Service renderers now use BPRoute for navigation, actions, forms and embedded HTML. The lower-level resolver is `ctx.route()`, shared by API handlers and views. This is a breaking release: `routeUrl`, `uiRouteUrl`, `ctx.url`, `routeUi` attribute helpers and BPElement are removed, with build/ESLint diagnostics directing authors to the replacement.

Route results retain six explicit destination fields. String conversion uses apiPath in API handlers and viewPath in renderers, never a UI field. Immutable `.component(id)` and `.fragment(id)` selectors preserve context. Current-route presentation metadata moves to `ctx.routeInfo` (native `route_info`/`RouteInfo`). Use `@betterportal/framework` as jsxImportSource for route-valued attributes and state overrides.

BPRoute states select their own element: state `as` and HTML/HTMX properties override outer defaults. Success controls support valueless hx-get/post/put/patch/delete markers, explicit destination overrides and native form validation. Failed controls can become plain text, images, labels or disabled buttons. Component/fragment props select GET embedding; bp-ok optionally wraps fetched HTML, ignores authored children/actions and requires no authored template placeholder. Authentication, permission, resolution and request failures remain separate states; failed mutations never automatically replay.

All repository services, themes, examples, native definitions, TSDoc, Markdown and generated LLM/theme guidance are migrated. ESLint `betterportal/routing-contract` and the fatal prebuild/codegen checker share the authoring rules, including internal API URL payload provenance. See [BPRoute specifics and examples](../building/bp-route.md) and [ESLint/build diagnostics](../building/routing-lint.md).

## Plain service anchors and mounted UI paths

A service-rendered `<a href="/batches/1">1</a>` should resolve through its owning service's enabled GET page mount. The shared theme runtime adds `hx-get` for the service request, `hx-target="#bp-main"`, `hx-swap="innerHTML"`, and the mounted path for href/history. A UUID mount such as `/installed-service-id/batches/:batchId` must keep that prefix during navigation and Back/Forward.

Older/custom shells may publish `requestUrl` as `/batches/%3AbatchId` without separate service template metadata. The runtime now recognizes encoded parameter placeholders only when they correspond to parameters declared by the UI mount; it does not guess arbitrary child routes or prefixes. This fixes plain anchors that previously remained `/batches/1` on the theme origin.

`hx-preload` and `data-bp-preload-bound` are preload annotations, not proof that routing succeeded. The preload listener only fetches when an actionable hx-get exists. For a known page, inspect the generated hx-get/target/swap and mounted href, not the preload marker alone.

**Custom themes bundling the shared runtime need a rebuild/redeployment to receive this fix.** Update the runtime/framework dependencies and JSX source configuration together. Publishing or deploying the generic Bootstrap/embedded themes does not replace a custom theme's existing bundle. Provide complete servicePath/serviceBaseUrl/method/fixedParams metadata where supported; the encoded-placeholder handling is compatibility for older metadata.

Python publishing remains deferred as requested; this release publishes the Node workspaces. Native source definitions and conformance coverage are updated.

Ordinary service-rendered destinations resolve against the owning service before any UI alias. An identically named UI mount belonging to another service cannot take over the link. Shell-owned navigation is explicitly marked. A configured UI path is a compatibility fallback only when no owning service destination matches.
