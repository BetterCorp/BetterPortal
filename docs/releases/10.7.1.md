# BetterPortal 10.7.1

This patch strengthens the fatal route authoring check for two response patterns found in the final review of 10.7.0:

- Explicitly rejected promise reasons retain provenance in `catch` and the rejection callback of `then`, including local recovery helpers and pass-through `then`/`finally` chains.
- Local response factories invoked with `call`, `apply` or `bind` retain their response and argument provenance, including bound callbacks used by promise and collection operations, static spread arguments and callbacks stored in known object fields.

Recovery that returns domain data, public links and opaque domain-client results remain valid. Docs and the hello-view example explain the supported static patterns and the limits of source analysis. The routing runtime and the six-field `routeUrl(input?)` contract are unchanged from [10.7.0](https://github.com/BetterCorp/BetterPortal/releases/tag/v10.7.0).

Validation: 190 framework tests, compilation, all service source gates and lint pass. BSB remains 9.7.4 and AnyVali remains 1.1.6, verified as latest on 2026-10-12. Python/PyPI publication remains deferred in PR #105. All release PRs must merge before this patch is tagged.

Final checks also cover rest parameters, explicit rethrow/re-reject handlers and ignored extra promise arguments.
