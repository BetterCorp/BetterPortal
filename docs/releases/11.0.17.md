# BetterPortal 11.0.17

## Config sync startup and PostgreSQL

Config Manager now gives a bootstrap poll a 20-second server budget. The Node client allows 30 seconds per POST and retries with jitter and capped backoff. Its authenticated readiness details report the most recent outcome, correlation ID and age of the last successful sync. The client stays unready until it accepts a valid configuration. The bundled Easy1 services have a 60-second startup grace period.

Match the client's correlation ID to the server's structured request summary to locate a delay in authentication, validation, the metadata queue, config loading, route reconciliation, config saving or projection. Retryable failures return HTTP 503 with Retry-After and a reason code. SSE stream lifetime is separate from POST duration.

A fresh PostgreSQL 16 database reproduced a blocked metadata write. A 250 ms request budget used to leave a writer waiting for the database fixture's 10-second timeout. With the fix it returned in 252 ms and rolled back. In a separate four-service POST test, three cold services bootstrapped in 95 ms while the first service's lock remained held after cancellation. The first service recovered after the lock was released. These are isolated test measurements.

The PostgreSQL writer retains revision and dependency locks for atomic registration. It now bounds sync statements and removes one redundant full configuration read while holding those locks. Cancelled requests leave the application queue, unchanged retries preserve config revisions, and repeated polls within a minute avoid rewriting presence rows unless a new manifest needs delivery confirmation.
