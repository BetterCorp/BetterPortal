# BetterPortal 11.0.16

## Service validation fragments

Explicit service status renderers honour fragment negotiation. Typed validation
responses can appear in local form error outlets while preserving entered
values. Full status pages, authentication errors and JSON responses retain
their existing representations. This includes the unchanged status-fragment
fix from PR #184.

## Independently authenticated native protocols

Node BSB services can register a native protocol handler and its narrow transport policy through `registerProtocolEndpoint` in `onRegistered`. This supports maintained OAuth authorization-server callbacks and authenticated MCP resources alongside ordinary BP views without pretending that an external protocol credential is a BP bearer.

Each endpoint declares one explicit path, its methods, browser origins, request headers and exposed response headers. Named single-segment parameters are supported; wildcard paths, ambiguous registrations, generated BP route collisions and replacement of BP authentication, management or SEO paths are rejected. Only literal well-known GET/HEAD metadata can declare non-credentialed wildcard CORS. A denied origin or unsupported preflight never invokes the handler. A matched endpoint cannot fall through into business routing.

The owner handler supplies protocol authentication, resource/audience validation, current-grant authorization, request limits and readiness. Registration creates no BP user, tenant/app or service context and does not change ordinary BP CORS or route permissions. H3's public Node callback adapter is supported, including repeated owner `Set-Cookie` headers for a library-managed OAuth transaction.

See the [service authoring guide](../building/services.md#independently-authenticated-protocol-endpoints) and [security boundaries](../platform/security-and-auth.md#separate-native-protocol-policies). Consumers must use the actual published release that includes the API; local build archives are compatibility evidence rather than a production dependency override.

## TLS offloading

Native integrations must preserve the existing direct-peer proxy trust policy. `BPService.headerTrustOptions(event)` enables forwarded-header interpretation only for a configured `trustedProxyIps` peer and the corresponding enabled trust flag. Compute a canonical protocol URL with the public H3 URL helper and those verified options; do not trust client-supplied forwarded hosts or schemes globally. An OAuth library's proxy mode must remain behind the same checked ingress boundary.

The API is additive. Existing BP 11.0.15 operation grants and full-manifest rollout requirements remain in force.
