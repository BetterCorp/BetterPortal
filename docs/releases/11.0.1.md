# BetterPortal 11.0.1

Config Manager now consolidates equivalent preview API mounts when separate operation mounts migrate to the same generated URL. A report view with GET, PUT and DELETE no longer causes a duplicate-mount HTTP 409 during staging refresh. The first mount ID, route position and compatible settings survive.

Valid custom aliases keep their paths and selected operations; distinct service-path variants remain separate. Generated API mounts include current operations, while conflicting settings or unrelated routes still fail with HTTP 409. Regression coverage exercises actual deployment POST refreshes, repeated reconciliation, same-key redeployments, aliases and conflicts.

Upgrade Config Manager and rerun the failed staging deployment. Keep staging and report service URLs intact. See [preview deployment operations](../operations/preview-environments.md#api-mount-migration-during-refresh) for the migration example and retry semantics.
