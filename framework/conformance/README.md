# BP cross-language conformance

**Gate blocked: the .NET/Python framework ports are not implemented yet.**
This directory supplies the first reproducible gate: canonical contracts,
native AnyVali adapters, HTTP fixtures, and a capability/acceptance ledger.
It does not claim runtime, crypto, authoring-tool, or Bootstrap interoperability.

## Recorded result

With published AnyVali **1.1.0** in Node, Python, and .NET, **337 of 432**
scenarios pass. Each language receives the same 17 semantic cases and 127
canonical-document import cases. The [machine-readable report](results-anyvali-1.1.0.json)
records every result. The .NET package version/content hash is pinned in
[packages.lock.json](../dotnet/BetterPortal/packages.lock.json); Python's probe
dependency is pinned in [requirements.txt](requirements.txt).

| Failure | Evidence | Consequence |
|---|---|---|
| Imported sensitive metadata disappears in all three languages | sensitive-encrypt, sensitive-reject-plaintext-storage, sensitive-decrypt | Native sensitive callbacks are skipped and plaintext passes encrypted-storage validation. |
| Python rejects exported record/wrapper field names | recursive-json, config-state-defaults, import-JwtClaimsSchema, import-ScopedServiceConfigSchema | Published importer expects values/schema where Node exports valueSchema/inner. |
| .NET loses explicit null defaults | default-null | Missing required nullable values fail instead of materializing null. |
| Native export loses recursive definitions | recursive-export-reimport | Reimported JS/.NET documents contain unresolved BetterPortalJsonValue references; Python fails earlier on record import. |

The supplemental documents are generated by native Node schema authoring.
[export-fixtures.mjs](export-fixtures.mjs) first verifies the expected behavior
before interchange. The encryption callbacks deliberately use reversible test
markers to observe sensitive traversal; these are **not cryptographic fixtures**
and never ship as encryption implementations.

The gate intentionally returns a nonzero exit status. Do not change failing
expectations to reproduce defects. An upstream AnyVali fix or explicitly agreed
compatibility adapter must address these issues before contracts/security and
runtime work can pass their gates.

## Run from the repository root

Use Node with the workspace dependencies installed, .NET 10, and Python 3.10+.
The recorded run used Node 24.4.0, .NET SDK 10.0.201, and Python 3.13.5 on Windows;
Python 3.10 and Linux execution are still acceptance work.

```sh
npm run build --workspace @betterportal/framework
node framework/conformance/export-contracts.mjs --check
node framework/conformance/export-fixtures.mjs --check
python -m pip install -r framework/conformance/requirements.txt
dotnet build framework/dotnet/Conformance
python framework/conformance/verify.py --report framework/conformance/results-anyvali-1.1.0.json
```

If AnyVali is installed in a separate virtual environment, pass its interpreter
to verify.py using --python. The orchestrator itself uses only the standard
library. It launches disposable servers on available loopback ports, runs the
same HTTP requests against each, and stops all children even on failures.
The adapters are test-only endpoints that accept schema documents; never mount
them on a consumer application's public surface.

The HTTP runner can also target independently launched adapters:

```sh
python framework/conformance/run.py http://127.0.0.1:8310 http://127.0.0.1:8311 http://127.0.0.1:8312 --all-contracts
```

## Regenerate development artifacts

```sh
npm run build --workspace @betterportal/framework
node framework/conformance/export-contracts.mjs
node framework/conformance/export-fixtures.mjs
```

The exporter reads all canonical BP schemas from the compiled Node framework.
It includes the existing recursive JSON definition and exports bounded platform
menu schemas natively, without applying application-data depth limits to schema
documents. The scoped schema is derived from platform fields in
[scopedConfig.ts](../nodejs/src/contracts/scopedConfig.ts).

These JSON files are the shared source for subsequent native type generation.
Node is a repository development tool here; consumer wheels/NuGet packages must
embed the artifacts and must never invoke Node or BSB during build or runtime.
The current .NET adapter embeds the corpus; Python reads it from this checkout.
Python wheel packaging and native type generation remain pending.
